# Contribuindo

## Fluxo de trabalho

1. Parta da branch `main` atualizada.
2. Crie uma branch curta e descritiva para cada alteração.
3. Mantenha commits pequenos, com mensagem que descreva o resultado.
4. Execute a rotina de qualidade descrita em `DEVELOPMENT.md` antes de abrir um pull request.

## Limites de segurança

- Não adicione credenciais, URLs assinadas, tokens, fotos de clientes ou dados pessoais ao repositório.
- Não altere regras de Supabase/RLS, permissões de download ou a visibilidade de galerias sem revisão específica.
- Mudanças que envolvam upload, processamento ou download devem testar também o caminho de negação de acesso.

## Pull requests

Descreva o objetivo, os arquivos afetados, as verificações realizadas e qualquer ponto que ainda dependa de Supabase, hospedagem ou teste manual.
